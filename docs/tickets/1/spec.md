# Spec — 建立公司資訊(名稱 + 統一編號)CRUD(Issue #1)

## 來源

- Intent:#1
- 串接第三方單位:無

## 需求描述

1. 業務人員可以新增一筆公司資料,至少包含「公司名稱」與「統一編號」兩個欄位。
2. 統一編號需符合台灣統編格式(8 碼數字)並通過統編檢查碼演算法驗證,格式不符時
   拒絕建立/更新並提示錯誤。
3. 統一編號視為唯一鍵:新增或修改時若與既有(未刪除)資料的統一編號重複,拒絕
   該筆操作並提示錯誤。
4. 業務人員可以查詢(列表 / 依條件查詢)已建立且未被刪除的公司資料。
5. 業務人員可以修改既有公司資料的「公司名稱」與「統一編號」(修改後仍需符合
   第 2、3 點的驗證)。
6. 業務人員可以刪除既有公司資料,刪除採軟刪除(標記刪除狀態,不從資料庫移除,
   刪除後不再出現於查詢結果)。

## 驗收條件(Acceptance Criteria)

- [ ] AC1:Given 業務人員在新增公司資料頁面,When 輸入公司名稱與「格式合法」的統一
      編號並送出,Then 系統成功建立一筆公司資料並可在列表中看到。
- [ ] AC2:Given 業務人員在新增或修改頁面,When 輸入的統一編號不是 8 碼數字或未
      通過檢查碼演算法,Then 系統拒絕該筆操作並提示格式錯誤。
- [ ] AC3:Given 系統中已有一筆統一編號為 X 的公司資料,When 業務人員新增或修改
      另一筆資料為相同統一編號 X,Then 系統拒絕該筆操作並提示重複錯誤。
- [ ] AC4:Given 系統中已有公司資料,When 業務人員查詢,Then 能看到未被刪除之
      資料的公司名稱與統一編號。
- [ ] AC5:Given 系統中已有一筆公司資料,When 業務人員修改其公司名稱或統一編號為
      合法且不重複的新值並送出,Then 該筆資料被更新且查詢時顯示新值。
- [ ] AC6:Given 系統中已有一筆公司資料,When 業務人員執行刪除,Then 該筆資料
      不再出現在查詢結果中,但資料本身仍保留於資料庫(軟刪除)。

## 範圍外(Out of Scope)

- 公司資料以外的其他客戶相關欄位(如聯絡人、地址、產業別等)不在本次範圍。
- 權限控管(哪些角色可以新增/修改/刪除)不在本次範圍。

## 開放問題

| 問題 | 決議 | 決議人 |
|------|------|--------|
| 統一編號是否需要格式驗證(例如台灣統編 8 碼數字檢查碼)? | 需要格式驗證,套用台灣統編檢查碼演算法 | Dylan |
| 同一統一編號重複建立時如何處理(允許重複 / 阻擋 / 提示)? | 阻擋(視為唯一鍵,不允許重複) | Dylan |
| 刪除是軟刪除(可復原)還是硬刪除(直接移除)? | 軟刪除(可復原) | Dylan |
